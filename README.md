# UniWay - Backend & Machine Learning Engine

This repository contains the production backend architecture, API services, and Machine Learning pipelines for **UniWay**, an AI-powered Augmented Reality (AR) indoor navigation application designed for university campuses.

---

## Production API Endpoints (Live)

The application ecosystem is fully integrated and live. The core services are hosted on Hugging Face Spaces:
* **Base URL:** `https://rayouf0-uniway-backend-core.hf.space`

---

## Technical Breakdown: What We Built

### 1.Machine Learning & Computer Vision Pipeline (`ML`)
We implemented a robust computer vision system tailored for campus interior environments, divided into two primary operations:
* **Signage Object Detection (`UniWay_Detection_YOLOv8.ipynb`):** 
  * Trained a **YOLOv8** model to automatically detect and localize indoor signs, room plaques, and directory boards within campus corridors.
  * Optimized bounding box accuracy to handle varying lighting conditions and camera angles from the mobile client.
* **Text Recognition / OCR (`UniWay_Recognition_OCR.ipynb`):**
  * Integrated **EasyOCR** to handle text localization and character extraction directly from the cropped bounding boxes generated by the YOLOv8 model.
  * Pre-processed detected text to reliably read classroom numbers and departmental names, passing the extracted strings directly into the routing backend.

### 2.Asynchronous Backend Architecture (`Backend`)
To support concurrent users navigating the campus simultaneously, we built a highly efficient server environment:
* **Core Framework (`main.py`):** Structured the entire ecosystem using **FastAPI**, leveraging asynchronous Python (`async/await`) to minimize response latency during high-traffic campus hours.
* **Cloud Infrastructure & Security (`serviceAccountKey.json`):** 
  * Bound the backend with **Firebase** services to manage real-time updates and cloud synchronization.
  * Secured student data and device states using token management directly integrated via Firebase Admin SDK.

### 3.API Integration & Service Endpoints (`API`)
We designed clean, RESTful API routing layers to bridge the communication gap between the mobile app (React Native) and the AR subsystem (Unity):
* **Signage Prediction Routing (`POST /predict`):** Receives raw multipart form-data image frames from the user's camera screen, executes the combined YOLOv8 + EasyOCR pipeline, and returns the verified room destination instantaneously.
* **Smart Search Engine (`GET /classrooms/search`):** Handles native textual queries across campus buildings, mapping string fragments to active database classroom records.
* **User Bookmark Engine (`GET /bookmarks/my` & `POST /bookmarks/add`):** Manages local device identification headers (`x-device-id`) to seamlessly save, persist, and fetch custom user routes and bookmarked destinations without forcing tedious registration flows.
* **Endpoint Auditing (`API_Architecture_and_Testing.ipynb`):** Built automated testing scripts to simulate integration loads, verify payload schemes, and analyze routing stability before production delivery.
